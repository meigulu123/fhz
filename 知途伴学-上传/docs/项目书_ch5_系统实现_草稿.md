# 第五章 系统实现

本章按功能模块介绍系统实现：每个模块给出功能描述、实现要点与运行效果。
系统全部功能在**无任何 API Key 的离线环境下**即可完整运行（MockLLM 兜底），
配置真实大模型 Key 后同一套代码无缝切换。

## 5.1 开发环境与总体结构

| 项 | 内容 |
|---|---|
| 开发语言 | Python 3.12 |
| UI 框架 | Streamlit（单进程、零前端代码） |
| 数据存储 | SQLite（WAL 模式，本地文件库） |
| 可视化 | plotly + networkx（图谱布局） |
| 中文分词 | jieba（记忆检索关键词） |
| 大模型接入 | openai 兼容 SDK + 自研 MockLLM 离线兜底 |
| 测试 | pytest + Streamlit AppTest（无头 UI 测试） |

运行时依赖仅 7 个开源库，无 Neo4j/Milvus 等外部服务。**一条命令启动**：

```bash
pip install -r requirements.txt
streamlit run app.py
```

## 5.2 学情诊断模块

**功能描述**：通过 4 问对话（称呼/学校专业/数学与机器学习基础/学习目标）采集背景，
再以自适应测验沿主链双向搜索定位水平边界，输出学生画像（先验/目标/风格标签）与
诊断报告（强弱节点/ZPD 带/建议起点）。

**实现要点**：

- 新学生点击「登录/开始学习」后直接进入 DIAGNOSING 状态，开场白即带第一问
  （"你好，我是知途伴学……怎么称呼你？"），减少交互轮次；
- 先验解析用规则引擎（`PRIOR_RULES` 词表匹配 + 程度词降级），目标解析映射到图谱
  关键词集（"深度学习"→14 个相关节点），直接驱动路径评分的目标相似度项；
- 自适应测验由 `AdaptiveQuiz` 类驱动：答对沿主链上跳、答错下钻未覆盖先修，四个
  终止条件（覆盖≥6 主链节点 / ≥12 题 / 连续 4 题对错交替 / 题库耗尽）保证快速收敛；
- 测验逐题实时更新掌握度并落库，诊断报告与 ZPD 带直接作为路径规划输入，形成闭环。

## 5.3 路径规划模块

**功能描述**：基于诊断画像输出学习路径：拓扑序保证先修在前，ZPD 带分档（主修/复习/
暂缓），五维评分排序，节奏参数决定每批学习量；支持手动重新规划与动态重规划。

**实现要点**：

- `PathPlanner.plan(profile, batch)`：Kahn 拓扑分层 → 前沿集过滤（先修加权均值
  ≥0.6 且 θ<0.75）→ ZPD 三档 → 评分（0.30·ZPD+0.25·(1−θ)+0.20·中心性+0.15·目标
  相似度+0.10·认知契合）贪心选批；
- 节奏参数 `pace = clip(0.5+0.8(acc−0.70)−0.10·stuck, 0.4, 1.6)`，batch=round(3·pace)：
  测验正确率与卡住次数共同决定学习节奏；
- 每次规划版本落库（study_plans 表），路径页可查看历史版本；
- 动态重规划：卡死 L3/先修崩塌/目标变化/反思建议四类触发，LLM 输出结构化 JSON
  （Mock 模式规则兜底），回补最弱先修节点并插入计划队列。

## 5.4 实时干预模块（脚手架）

**功能描述**：学生答错或表达困惑时，不公布答案，而是按 L0 苏格拉底反问 → L1 概念
提示 → L2 类比样例 → L3 分步解析 + 变式检验逐级支撑；答对即退出并记录提示档案。

**实现要点**：

- 卡住判定为 OR 信号组（连错≥2 / 近3轮正确率<1/3 / 困惑词 / 连续2轮求助），
  由 `detect_stuck` 实现并实时监控；
- 提示素材锚定题库 hints 字段与讲义 `[ASK:]` 提问位（L0 反问优先取提问位），
  Mock 模式完全由数据驱动、不依赖模型生成——防幻觉的关键设计；
- 变式检验：L3 解析后换表述与数据出变式题，答对才算"真理解"；变式仍错触发
  LLM 重规划，回补当前节点最弱的先修（干预与路径规划联动）；
- 每次提示使用记录落库（hint_usage 表），形成学生提示档案供反思分析。

## 5.5 记忆与反思模块

**功能描述**：SQLite 7 表完整记录学生画像、会话、交互、掌握度快照、反思摘要、计划
版本与提示记录；会话结束/节点完成/卡死/周期四类时机触发反思；新会话开场白引用
上次学习记忆，实现跨会话教学连贯。

**实现要点**：

- 全表操作线程安全（`check_same_thread=False` + 全局读写锁），适配 Streamlit
  多线程 rerun；
- 掌握度快照按知识点落库，画像页趋势线直接读取快照序列；
- 反思由 LLM 压缩生成四段式输出（进展/有效策略/计划调整/下次预告），Mock 模式
  模板兜底；LLM 失败不影响主流程（try/except 保护）；
- 「结束」进入 REFLECTING 状态完成反思落库；说「继续」即开新会话并引用
  next_session_preview（"欢迎回来，上次你卡在……"）。

## 5.6 知识图谱可视化模块

**功能描述**：50 节点知识图谱网络图：节点颜色 = 掌握度（红→黄→绿），金色描边 =
当前学习路径，星标 = 正在学习的知识点，先修边按拓扑层从左到右布局。

**实现要点**：

- networkx 计算拓扑层与度中心性（布局 + 评分复用同一图结构）；
- plotly 手绘节点/边轨迹（无依赖额外图布局库），悬停显示知识点名称与掌握度；
- 颜色映射 RdYlGn 色带，与画像页/路径页配色一致。

## 5.8 状态探针与工程质量

**功能描述**：开发自检页（也是工程质量的体现）——验证 AgentState 在 Streamlit
全脚本 rerun 后完整存活、可序列化往返，并实时展示状态完整性清单。

**实现要点**：

- Streamlit 每次交互都会整脚本重跑，Agent 状态必须完整驻留 session_state；
  探针页作为 P4 阶段门禁：修改状态→点按钮触发 rerun→断言状态不丢，通过后才
  开发业务页面（先验证地基再盖楼）；
- 序列化往返断言：to_dict→from_dict→to_dict 全等，保证状态可持久化到任意介质；
- 四项完整性清单：画像对象/掌握度条目数=图谱节点数/对话历史/计划结构。
