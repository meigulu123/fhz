# 第4章 系统测试

本章回答一个朴素的问题：系统宣称的每一项能力，凭什么可信？知途伴学的做法是把"教育学正确性"翻译成一条条可自动执行的断言——知识图谱有没有环、掌握度更新是否符合公式、路径推荐是否落在最近发展区内、脚手架是否只引导不代答、记忆是否真的跨会话延续——全部用测试代码验证，而非口头描述。全章共 107 项自动化用例（104 个测试函数，test_assets 按 4 个资源名参数化展开），按 P1（知识图谱/掌握度/路径规划）→ P2（学情诊断）→ P3（脚手架/记忆）→ P4（端到端/UI）四级优先级分层设计与执行，全部离线运行、零外部服务依赖、一条命令可复现。

设计原则有三条：其一，每个用例的预期结果必须对应测试代码中的一条真实断言，断言即规格；其二，依赖最小化——LLM 层全部由 MockLLM 离线桩接管，数据库全部落在 pytest 临时目录，测试之间互不污染；其三，可复现——任何评审者克隆仓库后执行 `python -m pytest tests/` 一条命令即可在无网环境得到同一结果。

需要说明的是，107 项用例在设计与执行上均不依赖任何外部服务：无网络请求、无 API 调用、无第三方数据库（LLM 兼容层的网络行为经本地假服务验证），运行环境与本机演示环境完全一致。这一特性同时支撑了 4.6 节的离线可用性验证——测试与离线演示共用同一套 Mock 运行方式。

**"状态持久化探针"的工程意义**：Streamlit 的每一次交互都会自上而下重新执行整份脚本（rerun），这意味着会话状态必须完整驻留在 session_state 中才能跨交互存活；同时 AgentState 必须能通过 to_dict/from_dict 序列化往返，页面刷新与恢复时才不会丢状态。探针页把这两件事固化为两项可点击的门禁断言——"rerun 后状态存活"与"序列化往返一致"。任何一次重构若破坏了状态驻留或序列化能力，探针页与 T-UI-02 会立刻失败。这是智能体"跨会话续学"承诺在工程上的底线保障。
