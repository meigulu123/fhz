# 学生画像页需求与设计文档

> 版本：v1.0　日期：2026-09-14　适用范围：知途伴学 · Streamlit 学生画像页

## 一、需求梳理

### 1.1 核心目标

学生画像页是系统"学情诊断"能力的**可视化出口**：基于学生历史学习、错题、答题数据，
自动量化学情，可视化学生知识短板与学习行为特征，输出学情诊断结论，为自适应学习
路径提供依据。

一页之内回答三个问题：

| 评审视角的问题 | 页面回答 |
|---|---|
| 学生学得怎么样？ | 六维能力雷达、核心能力分、4 项学习指标卡 |
| 短板在哪里、为什么？ | 知识点掌握度表、ZPD 分布、布鲁姆认知层级、错题统计 |
| 下一步怎么学？ | AI 学情诊断（优势/薄弱/建议）、掌握度趋势 |

## 二、指标定义与计算公式

### 2.1 基础量：知识点掌握度 θ

单个知识点的掌握度 θ 是全系统数值核心，采用 **BKT（贝叶斯知识追踪）简化 + Elo 自适应
学习率** 的混合更新（理论出处：Corbett & Anderson, 1995；Elo 评分机制；本项目实现于
`src/student/update.py`）：

```
p(答对概率) = 1 / (1 + exp(−8·(θ − 0.5)))        —— logistic 能力曲线
θ' = θ + K · (c − p)                              —— 作答更新，c=1 答对 / c=0 答错
K = K_base · (1 − n / (n + 3))                    —— 学习率随证据量 n 衰减
K_base = 0.18（测验） / 0.09（对话软证据）
θ ← θ · exp(−0.02 · Δt天)                         —— 遗忘衰减
```

- 初始值：`θ₀ = clip(0.25 + 0.40·prior + 0.35·先修均值 − 0.15·I[存在先修 θ<0.6], 0.05, 0.85)`
- 先修传播：答对后继 +0.05；答错先修 −0.03 并标记待复习
- 状态分档：θ ≥ 0.75 **已掌握**；0.05 < θ < 0.75 **学习中**；θ ≤ 0.05 **未开始**

### 2.2 六维学习能力（0~100，雷达图 F1）

| 维度 | 计算公式 | 教育理论依据 |
|---|---|---|
| 学习进度 | `已掌握节点数 / 图谱总节点数 × 100` | 目标参照评估：课程完成度 |
| 知识掌握 | `mean(θ_k) × 100`，k 遍历全部知识点 | BKT 掌握度均值（知识追踪） |
| 逻辑理解 | `mean(θ_k) × 100`，k 为布鲁姆层级 ≥ 4（分析/评价/创造）的节点 | 布鲁姆认知目标分类：高阶认知能力（Bloom, 1956; Anderson & Krathwohl, 2001） |
| 答题正确率 | `答对题数 / 总做题数 × 100`（无作答记 0） | 证据中心设计（ECD, Mislevy）：作答表现为核心证据 |
| 记忆巩固 | `mean(min(evidence_k / 8, 1)) × 100`，k 遍历已掌握节点 | 间隔重复与过度学习：8 次练习证据为巩固饱和线 |
| 学习投入 | `min(总学习时长秒 / 36000, 1) × 100`（10 小时满格） | 学习投入度（学生参与度研究，Fredricks 等） |

### 2.3 ZPD 最近发展区（散点分布图 F7）

维果茨基最近发展区（Vygotsky, 1978）在路径规划中的数值化（`src/path/planner.py`）：

```
z_low  = mean(θ_k)                                  —— 当前平均水平 = 区带下限
z_high = min(mean(θ_k) + 0.15 + 0.35·σ(θ_k), 0.95)  —— 上界随波动自适应，封顶 0.95
```

图中每个点是一个知识点，横轴为节点难度（0~1），纵轴为掌握度 θ；三个色带：
难度 < z_low 为**复习带**（回补巩固），z_low ~ z_high 为 **ZPD 带**（主修区），
> z_high 为**暂缓带**（暂不排入）。路径规划仅从 ZPD 带选取节点，实现"跳一跳够得着"。

### 2.4 布鲁姆认知层级（柱状图 F8）

按掌握度加权的认知水平（`src/student/profile.py::cognitive_profile`）：

```
认知水平 L = Σ(θ_n · bloom_n) / Σ θ_n            —— 加权平均层级（1=记忆 … 6=创造）
分布图：每个层级 1~6 的柱高 = 该层级全部节点的 mean(θ)
```

理论依据：布鲁姆认知目标分类学（Bloom, 1956）——低层级（记忆/理解/应用）达标但
高层级（分析/评价/创造）薄弱，说明"会算不会用"，诊断报告据此给出针对性建议。

### 2.5 数据来源（SQLite，全部本地）

| 数据 | 表/来源 |
|---|---|
| 掌握度 θ、练习证据数 | mastery_snapshots（每节点最新快照） |
| 做题数/错题数/正确率 | interactions（kind='quiz'，解析 mastery_delta_json） |
| 学习时长 | interactions 的 ts 按「活跃时长」口径累计（见下） |
| 每日时长 | interactions 按交互时间分桶到近 7 天，桶内同口径累计 |
| 趋势图 | mastery_snapshots 全量历史 |
| 观察记录时间线 | profile_observations（时间/触发原因/画像增量 JSON） |

活跃时长口径：交互时间戳排序后，相邻间隔 ≤ 10 分钟视为连续学习、
间隔全部计入；超过 10 分钟视为挂机/离开、间隙不计；单条交互至少计 1
分钟。不依赖 sessions 的登录时间，挂机不再虚增学习时长。

## 三、页面 UI 改版描述

整体延续深色科技风（深空蓝底 + 青色 #22d3ee 强调，与全站玻璃卡片一致）。
自顶向下六个区块，标题分两级：一级 `section-title`（区块），二级为图表自带标题。

```
┌─ 页头 chat-banner：左「长期目标 + 目标文本」，右上「知途伴学 · 学习数据看板」
│  └─ 新增：学生切换 selectbox（右侧，列出库内有学习数据的学生，默认当前学生）
├─ 能力概览（3 列）：六维能力雷达 | 掌握度三档环形 | 核心能力分卡片
├─ 学习数据概览（4 指标卡，hover 上浮动效）：总做题数 | 错题数 | 正确率 | 总学习时长
├─ 学习分析（2×2 四图）：近7天时长柱状 | 做题正确率环形 | ZPD 分布散点 | 布鲁姆层级柱状
├─ 知识点掌握度（雷达 + 详情表）：
│    表格按掌握度降序默认排序，支持点表头切换排序；
│    掌握度列用进度条（渐变着色），状态列：已掌握=绿 / 学习中=青 / 未开始=灰
├─ 基本信息与诊断报告：左基本信息，右 AI 学情诊断（LLM 生成，优势/薄弱/建议三段）
├─ 大模型观察记录：时间线（时间 · 会话结束/空闲跟进：新增标签/目标更新/观察结论），
│    空态给出引导文案
└─ 掌握度变化趋势折线图（底部全宽）
```

- 模块间距：区块间 20px，区块内图表 margin 收紧（t=46 标题行），消除大片留白
- 空状态：未诊断/无作答时，六维雷达、占比环、ZPD、布鲁姆、正确率、时长图显示
  「暂无学习数据」居中提示；表格显示空表；诊断报告显示引导文案

## 四、图表配置优化（plotly，深空蓝+青主题）

统一由 `dark()` 套深色主题。本轮增强点：

1. **悬浮 tooltip（含指标解释）**：六维雷达悬浮显示"维度名：分数 + 该维度计算定义"；
   ZPD 散点悬浮显示"知识点名 + 难度 + θ + 所在带名"；布鲁姆柱悬浮显示"层级名 +
   平均掌握度 + 该层节点数"；柱状/环形图悬浮显示数值与占比。
2. **标题与图例**：每张图自带标题；占比环/正确率环横向图例置于底部。
3. **配色**：主色 #22d3ee（青）、成功 #34d399（绿）、警示 #f87171（红）、
   中性 #475569/#94a3b8；ZPD 三带沿用黄（复习）/青（ZPD）/灰（暂缓）半透明叠加。
4. **空状态**：数据为空时用 plotly annotation 在图中居中显示提示，不中断页面布局。

（说明：本项目图表统一使用 plotly 而非 ECharts——离线可运行是竞赛演示的硬约束，
ECharts 依赖 CDN 或需打包 1MB 静态资源；plotly 已随 Python 包离线可用，且 tooltip/
图例/标题/配色能力对等。）

## 五、AI 学情诊断报告生成（后端）

### 5.1 生成流程

```
画像页渲染 → 计算画像指标指纹（学生ID + 关键指标 hash）
  → 缓存命中？  → 直接渲染
  → 未命中    → 调 LLM（真实模式走星火/DeepSeek，Mock 模式规则兜底）
             → 结果写入 session_state 缓存 → 渲染
```

- 指标变化（做完测验、学完节点）后指纹变化，下次进页自动重新生成 → 数据联动
- 切换学生 → student_id 变化 → 指纹不同 → 重新生成 → 诊断报告同步刷新（F12）

### 5.2 提示词模板（交给大模型）

```text
[TPL:profile_report]
你是知途伴学智能体的学情诊断专家。请根据下方学生画像指标，写一段
150~250 字的学情诊断，用 Markdown 分三小节：**学习优势**、**薄弱环节**、
**学习建议**。要求：
- 优势：结合掌握度高的知识类别、六维能力中的高分项与答题正确率，具体到知识点；
- 薄弱：结合 ZPD 带下方的低掌握度节点、待复习节点与布鲁姆认知层级短板，具体到知识点；
- 建议：结合 ZPD 带范围，给出一条可执行的学习路径建议（从哪个知识点入手、
  优先补哪类认知层级），一条行为建议（基于答题正确率与学习时长）；
- 语言像一位了解学生的老师，自然、具体、无空话套话，不出现"产业命题"等字样。

学生画像指标：
{指标 JSON：学生姓名/专业/目标；六维能力各分值；平均掌握度；已掌握数；
三档占比；ZPD 带；布鲁姆层级；答题正确率与总做题数；错题知识点列表；
学习时长；最强与最弱知识类别；待复习节点}
```

Mock 模式（未配置 API Key，离线演示）由规则模板生成同构三段文字，内容取自
真实指标，保证演示时报告"有据可查"。

## 六、画像持续更新（大模型观察记录，F16）

学生画像不是诊断后一成不变的快照，而是随对话持续生长的对象：

- **触发时机**：①每次结束会话时（`_end_session`）；②教学阶段空闲超过 5 分钟——
  回到画像页查看自己时先让大模型跟进一次再展示（`handle` 入口同样校验）；
- **生成方式**：把近期 10 条交互摘要与画像统计（做题数/正确率/已完成知识点/
  风格标签）交给大模型（模板 `TPL:profile_observe`），输出三类增量：`style_tags_add`
  （追加去重）、`goals_update`（整体覆盖）、`observation`（一段观察结论）；
- **兜底与门槛**：离线 Mock 模式走规则兜底（正确率 ≥0.7 记「答题节奏稳定」、
  <0.4 记「基础需巩固」，观察结论给出做题数与正确率）；全部输出为空则不落库，
  保证时间线条条有据；
- **展示**：profile_observations 表按时间倒序渲染为时间线，每条显示「MM-DD HH:MM ·
  会话结束/空闲跟进：新增标签/目标更新为/观察结论」，空态给引导文案。
